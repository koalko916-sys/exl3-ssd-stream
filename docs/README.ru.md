# EXL3 SSD Stream: инструкция

Экспериментальный запуск полного GLM-5.3 EXL3, 753B / 273 GiB, с SSD на Windows:
RTX 3080 10 GiB, Ryzen 5 7500F, 16 GiB RAM. Веса и квантование не изменены.
Вычисления и архитектуру предоставляет ExLlamaV3; здесь реализованы загрузка и кэши.

Версия 0.2 добавляет `--optimized`: прямое чтение SSD, предзагрузку экспертов,
MTP8 и поиск продолжений в проверенном контексте. **Каждое предсказание проверяет
полная модель**. Неподтверждённый текст не выдаётся.

Точное копирование: **1,167 ток/с**, 169 токенов; полный ответ — **318 с**,
первая выдача — **265 с**. Обычные тестовые запросы: примерно **0,21–0,40 ток/с**.
Универсальный 1 ток/с не достигнут. Скорость генерации исключает обработку промпта;
управляющий токен включён, EOS исключён из количества, но его вычисление входит во время.
Только видимый длинный ответ также превысил 1 ток/с: 1,160.

## Установка

Нужны Python 3.13, NVIDIA GPU, драйвер CUDA 12.8 и около 310 GiB свободного SSD.

```powershell
git clone https://github.com/koalko916-sys/exl3-ssd-stream.git
cd exl3-ssd-stream
powershell -NoProfile -File scripts/install-windows.ps1
.venv\Scripts\hf.exe download Infatoshi/GLM-5.3-UNCENSORED-EXL3-3.0bpw --revision d06b4f42db97c8bb7a8f72e819b979f132e4a721 --local-dir E:\models\glm53-exl3
.venv\Scripts\python.exe -m exl3_ssd_stream --optimized --mtp 8 --model E:\models\glm53-exl3 --interactive --context 2048 --tokens 256 --report last-response.json
```

Обновление существующей установки: `git pull`, затем
`.venv\Scripts\python.exe -m pip install -e .`. Веса скачиваются отдельно.

`/new` очищает историю, `exit` завершает процесс. Один экземпляр на GPU.
Ответ может занимать несколько минут. Копируемый текст появляется блоками после проверки.
Контекст 2048, максимум вывода 256 в примере; `--tokens` должен быть меньше контекста.
При заполнении контекста удаляются старые полные реплики.

Без `--optimized` запускается первоначальный адаптер. Ускоренный режим использует
Win32 и работает только на Windows. Linux для первоначального режима не проверен.
WARP и Linux-консоль для этого запуска не требуются.

## Настройки и ограничения

`--cache-gib` и `--host-cache-gib`: -1 выбирает автоматически, 0 отключает кэш.
Полная память процесса включает также KV, нормы, маршрутизаторы и временные буферы.
Автоматические резервы не гарантируют отсутствие OOM.

По умолчанию: два потока чтения, MTP8, lookup до 128 токенов, резерв RAM 1,25 GiB,
резерв GPU при выборе кэша 0,75 GiB, порог динамической защиты GPU 0,125 GiB перед
проверкой блока. Явные переменные окружения имеют приоритет.
`GLM_NGRAM_WINDOW=0` отключает lookup; `--mtp 0` отключает MTP и lookup.

Два потока SSD дали 2,08 GB/s; четыре и восемь медленнее. MTP16/32 и полностью
резидентный MTP не дали устойчивого преимущества. Слишком высокий порог защиты GPU
вытеснял полезные веса. Сохранены неудачные тесты, включая запуск с длинными задержками
без установленной причины. Результаты зависят от нагрузки и размеров выбранных кэшей.

Повторяющиеся фрагменты помогают lookup, новая генерация может не ускориться.
Большая пакетная проверка увеличивает ожидание первой выдачи.
